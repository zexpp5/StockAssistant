# AI 产业链覆盖机制与缺口扫描器

**日期**：2026-06-18
**状态**：①②③④⑤ 已落地（taxonomy + 缺口扫描 + audit/dashboard + 三桶12只补齐 + 当天价 + 分析师目标价 + 分层 ai_core + buy_zone 全点亮），⑥ ETF 发现层待做。9 环节全 covered。唯一仍欠：price_daily 历史序列（MA 路径），按日自然累积 ~50 交易日，无需动作。
**起因**：2026-06-17 排查发现 SIMO/WDC/SNDK 三只存储链龙头**完全不在系统里**，
雷达照不到、buy_zone 算不出。深挖后确认这不是"美股拉得太少"，而是
`system_universe` 的 AI 产业链种子有**结构性盲区**，且只能靠人临时聊天才发现。

---

## 一、问题定性（已核实，非推测）

| 现象 | 根因 | 证据 |
|---|---|---|
| SIMO/WDC/SNDK 不在雷达 | 雷达只重排已打分的推荐池，不新增候选 | `ai_radar.py:5` "不新增候选范围" |
| 这三只不在推荐池 | 没进 `system_universe`（133 只可打分宇宙的第一道门） | 全库 49 表扫描 0 命中 |
| 没进宇宙就没价格 | 数据跟着宇宙成员走，不收录就不抓价 | `price_daily` 0 行 |
| 存储链只有 MU 一只 | `us_universe.py` 种子桶缺"存储/光互联/先进封装"赛道 | `US_AI_TECH_UNIVERSE` 无相关条目 |
| 存储票即便进来也"不可买" | 不显式分层会落 `theme_watch`，而它不在可买层 | `tech_growth_layers.py:24` `BUYABLE_ALLOWED_LAYERS` 不含 theme_watch |

**结论**：不是拉价能力问题，是 universe **生成层**的覆盖偏科 + 缺自检机制。

## 二、目标与边界

**目标**：覆盖 AI 产业链的**关键环节**，每个环节至少有代表公司；但**只有可交易、可抓价、有链条证据**的票才进 `system_universe`。

**明确不做**：
- ❌ 不拉标普 500（噪音太大：300+ 非 AI 死重污染打分，且仍漏 SIMO/铠侠等非大盘/非美关键节点）。
- ❌ 不手工随便塞 30 只（要做成可自检机制，不是一次性补丁）。
- ❌ 不改打分公式（守 `feedback_no_secret_score_changes`，只动 universe 生成层）。

### 三个状态，别混淆（2026-06-18 review 修正）
```
discovery_candidate   发现到的候选，尚未校验，谁都能提（种子/ETF/宽扫/人工）
        ⊋
system_universe       可跟踪/可打分宇宙 —— 过了可交易+AI证据就进，无论可不可买
        ⊋
buyable               宇宙内、且分层落在可买层(BUYABLE_ALLOWED_LAYERS)的子集
```
> **实测佐证**：当前 US 宇宙 133 只里有 **54 只非可买层**（theme_watch 53 + excluded 1）
> 仍正常待在 `system_universe`。所以 `system_universe ⊋ buyable`，
> **不能"只让 buyable 进宇宙"**——否则 research_only/watch_only 票抓不了价、没法观察、永远翻不了绿。

### 闸门顺序（修正版）
```
发现候选 discovery_candidate
  ↓ 可交易 ticker 校验（规范化 → US/ADR 可交易 → 能抓价写 price_daily）
  ↓ AI 产业链证据（属不属于链 / chain_classifier 归类 / 证据来源）
进入 system_universe —— 标 source / segment / evidence（此刻就入池，可买与否不拦门）
  ↓ 抓价、补因子、补数据
  ↓ tech_growth_layers 分层
buyable / research_only / watch_only  ←  仅决定"推荐展示层级"，不决定是否在宇宙里
```
> ⚠️ 研究池 ≠ 可买池，但**两者都在 system_universe 里**。anchor 出现在 taxonomy 只代表
> "该环节标杆、用来度量覆盖"，**不等于已可交易、不会自动入池**——入池前的可交易校验是独立闸门。

## 四、第①步已落地内容

- `AI_SUPPLY_CHAIN_SEGMENTS`：9 条关键环节 taxonomy（单一来源），每条含

- `compute_chain_coverage(symbols)` → 每环节 `covered / thin / gap` + 命中/缺失龙头。

## 五、测试用例

`tests/test_ai_supply_chain.py`（14 用例，`python3 -m unittest tests.test_ai_supply_chain` 全过）：
- **T1** taxonomy 自洽：每环节有龙头、`min_covered` 合法且 ≤ anchor 数、key 唯一。
- **T2** anchor 格式：大写/非空/环节内不重复（粗筛可交易 ticker 格式）。

`tests/test_ai_theme_coverage_audit.py`：
- 验证 `ai_theme_coverage_audit` 只统计 `system_universe` 里的 active US 标的。
- 验证非 US / inactive 标的不会被误算成覆盖。

## 七、风险与方法边界

- **taxonomy 的 anchor 是"我俩列的候选"**，入池前一律过可交易校验（铠侠是日股→进不了 US 池，
  走 ADR 或排除）。本文列的 ticker 不可直接全信。
- **coverage 是"代表公司覆盖度"，不是"完整行业覆盖度"**。anchors 是每环节的标杆集，
  若未来有非 anchor 的优秀公司已在宇宙里，扫描仍可能把该环节报成 thin/gap（误报偏保守）。
  anchors 适合做 MVP 缺口提示；要逼近真·行业覆盖，需后续把 anchors 扩成"该环节全量代表池"。
- **覆盖扫描只能抓"链条级"盲区**（对照已定义的 taxonomy）。抓不到"我们都没想到的新主题"——
  那要靠后续"宽扫快照 + AI 关联闸"的发现引擎（见 `project_sandisk_bottleneck_radar`），非本需求范围。
- 新增/调整环节请只改 `AI_SUPPLY_CHAIN_SEGMENTS` 一处（单一来源）。
- **T4 是临时 tripwire**：补存储/光互联/先进封装桶的那个 commit，**必须同步更新 T4 基线断言**
  （否则会因"缺口已被填上"而故意失败）——这是预期信号，不是回归 bug。
