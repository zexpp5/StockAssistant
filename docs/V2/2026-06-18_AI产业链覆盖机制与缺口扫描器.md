# AI 产业链覆盖机制与缺口扫描器

**日期**：2026-06-18
**状态**：需求 + 第①步已落地（taxonomy + 缺口扫描核心 + 测试），②~⑤待施工
**起因**：2026-06-17 排查发现 SIMO/WDC/SNDK 三只存储链龙头**完全不在系统里**，
雷达照不到、buy_zone 算不出。深挖后确认这不是"美股拉得太少"，而是
`system_universe` 的 AI 产业链种子有**结构性盲区**，且只能靠人临时聊天才发现。

---

## 一、问题定性（已核实，非推测）

| 现象 | 根因 | 证据 |
|---|---|---|
| SIMO/WDC/SNDK 不在雷达 | 雷达只重排已打分的推荐池，不新增候选 | `ai_radar.py:5` "不新增候选范围" |
| 这三只不在推荐池 | 没进 `system_universe`（133 只可打分宇宙的第一道门） | 全库 49 表扫描 0 命中 |
| 没进宇宙就没价格 | 数据跟着宇宙成员走，不收录就不抓价 | `price_daily` 0 行 |
| 存储链只有 MU 一只 | `us_universe.py` 种子桶缺"存储/光互联/先进封装"赛道 | `US_AI_TECH_UNIVERSE` 无相关条目 |
| 存储票即便进来也"不可买" | 不显式分层会落 `theme_watch`，而它不在可买层 | `tech_growth_layers.py:24` `BUYABLE_ALLOWED_LAYERS` 不含 theme_watch |

**结论**：不是拉价能力问题，是 universe **生成层**的覆盖偏科 + 缺自检机制。

## 二、目标与边界

**目标**：覆盖 AI 产业链的**关键环节**，每个环节至少有代表公司；但**只有可交易、可抓价、有链条证据**的票才进 `system_universe`。

**明确不做**：
- ❌ 不拉标普 500（噪音太大：300+ 非 AI 死重污染打分，且仍漏 SIMO/铠侠等非大盘/非美关键节点）。
- ❌ 不手工随便塞 30 只（要做成可自检机制，不是一次性补丁）。
- ❌ 不改打分公式（守 `feedback_no_secret_score_changes`，只动 universe 生成层）。

## 三、三层方案（抽象层 → 真实文件）

| 层 | 做什么 | 真实文件 | 状态 |
|---|---|---|---|
| **① Taxonomy** | 定义"必须覆盖哪些 AI 子链" + 每链代表龙头参照集 | `stock_research/core/ai_supply_chain.py`（新增） | ✅ 已落地 |
| **② 候选发现** | 手工种子桶 + ETF 全成分 | `us_universe.py` 加桶；`fetch_theme_etf_holdings.py` 扩 Top-N | ⬜ 待做 |
| **③ 闸门** | 可交易 → AI 关联 → 链条 → 分层 → buyable/research/watch | `fetch_stock_prices.py`(抓价校验) + `tech_growth_layers.py`(分层) + `chain_classifier.py`(链条) | ⬜ 待做 |
| **覆盖自检** | 每天报"每条子链覆盖几只、缺哪些龙头" | 扩 `ai_theme_coverage_audit.py` 增 `_audit_chain_coverage()` | ⬜ 待做（核心模块已就绪可直接接） |

### 闸门顺序（每只候选必须依次过）
```
可交易 ticker 校验（能抓价→写 price_daily）
  ↓ 通过才继续
是否属于 AI 产业链  →  所属链条(chain_classifier)  →  证据来源
  ↓
分层(tech_growth_layers)：buyable / research_only / watch_only
  ↓ buyable 层
正式进入 system_universe
```
> ⚠️ 研究池 ≠ 可买池。anchor 出现在 taxonomy 只代表"该环节标杆、用来度量覆盖"，
> **不等于已可交易、不会自动入池**。入池前的可交易校验是独立闸门。

## 四、第①步已落地内容

### `stock_research/core/ai_supply_chain.py`（纯函数、只读、零 DB）
- `AI_SUPPLY_CHAIN_SEGMENTS`：9 条关键环节 taxonomy（单一来源），每条含
  `key / name / anchors(代表龙头) / min_covered / note`。
- `compute_chain_coverage(symbols)` → 每环节 `covered / thin / gap` + 命中/缺失龙头。
- `coverage_gaps(symbols)` → 只返回未达标环节（gap 优先），供早报/告警。
- `coverage_summary(symbols)` → 汇总计数，供 audit JSON / dashboard 顶部。

**语义边界**（避免与 `chain_classifier.chain` 冲突，见 `feedback_verify_identifier_semantics`）：
本模块 `segment` 粒度比 `chain` 更细（把粗粒度 "AI 算力" 拆成
memory_storage / optical_interconnect / advanced_packaging），**专供覆盖度量，不回写 chain_metadata**。

### 9 条环节当前覆盖快照（对 133 只 US 宇宙）
| 环节 | 状态 | 说明 |
|---|---|---|
| 算力芯片 | ✅ covered | 24 只，最强 |
| 半导体设备 | ✅ covered | ASML/AMAT/LRCX/KLAC/TER |
| 服务器/ODM | ✅ covered | DELL/HPE/SMCI |
| 电力/散热/数据中心 | ✅ covered | VRT/GEV/ETN/VST/CEG… |

| 边缘AI/机器人 | ✅ covered | ARM/QCOM/ISRG/SYM |

## 五、测试用例

`tests/test_ai_supply_chain.py`（13 用例，`python3 -m unittest tests.test_ai_supply_chain` 全过）：
- **T1** taxonomy 自洽：每环节有龙头、`min_covered` 合法且 ≤ anchor 数、key 唯一。
- **T2** anchor 格式：大写/非空/环节内不重复（粗筛可交易 ticker 格式）。
- **T3** 覆盖判定三态：covered/thin/gap 按规则正确；大小写不敏感；空宇宙全 gap 不崩。
- **T4** 基线缺口快照：拿真实 `us_universe` 种子跑，断言算力=covered、存储未覆盖(MU 在内)、
  光互联=gap。**此断言同时是 tripwire**——②补桶后会翻绿，提示同步更新基线，正是要的信号。

## 六、施工顺序（每步独立可验、可单独 commit）

```
① taxonomy + 缺口扫描核心 + 测试            ✅ 本次完成（只读零风险）
② 扩 coverage_audit 接 compute_chain_coverage → 每天 JSON 报缺口 + dashboard 显示
③ us_universe 加 存储/光互联/先进封装 三桶（候选清单先过目）
④ 每只新票过 fetch_stock_prices 抓价校验 → 通过的才落 system_universe
⑤ tech_growth_layers 给新票登记正确层（保证可买、不掉 theme_watch）
⑥ ETF 发现层扩 Top-N（收益最不确定，最后做）
```

## 七、风险与方法边界

- **taxonomy 的 anchor 是"我俩列的候选"**，入池前一律过可交易校验（铠侠是日股→进不了 US 池，
  走 ADR 或排除）。本文列的 ticker 不可直接全信。
- **覆盖扫描只能抓"链条级"盲区**（对照已定义的 taxonomy）。抓不到"我们都没想到的新主题"——
  那要靠后续"宽扫快照 + AI 关联闸"的发现引擎（见 `project_sandisk_bottleneck_radar`），非本需求范围。
- 新增/调整环节请只改 `AI_SUPPLY_CHAIN_SEGMENTS` 一处（单一来源），并更新 T4 基线断言。
