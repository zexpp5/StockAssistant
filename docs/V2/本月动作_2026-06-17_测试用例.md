# 本月动作 测试用例

日期：2026-06-17

产品位置：`AI 工作台 → 本月动作`

## 一、测试目标

验证 `本月动作` 页面是否符合页面级产品边界：

- 只读 advisory，不自动交易。
- 不写 `watchlist`，不写真实持仓。
- 不生成新股票池，不改变 AI 推荐排序，不改变 AI 组合方案。
- 可加仓最多 3 只。
- 单只超配和同赛道集中优先于新增买入。
- 参考价必须展示交易日或非实时口径。
- 策略验证未达标时必须写“研究候选，不是已证明买点”。

## 二、测试范围

覆盖：
- 页面入口。
- 策略验证提示。
- 可加仓清单。
- 纠偏 / 不再加。
- 本月不买原因。
- 参考价交易日展示。
- 静态代码边界。
- 自动化单元测试。

不覆盖：
- 真实下单。
- 手动编辑真实持仓。
- 修改 AI 推荐算法。
- 修改 AI 组合优化算法。
- 创建或维护 `watchlist`。

## 五、页面验收用例

### TC-UI-001 页面入口

步骤：
1. 打开 `stock_dashboard.html#monthly-actions`。
2. 查看 AI 工作台导航中是否存在 `本月动作`。

期望：
- 页面可以直接定位到 `本月动作`。
- 页面不是独立的新业务线，而是在 AI 工作台内。

### TC-UI-002 策略验证状态

步骤：
1. 查看页面顶部策略验证提示。
2. 当策略未达到真钱级验证时，检查文案。

期望：
- 页面明确写出“研究候选，不是已证明买点”或同等大白话。
- 不出现“强买入”“确定买点”等确定性交易措辞。

### TC-UI-003 可加仓数量

步骤：
1. 查看 `可加仓` 区域。
2. 统计展示股票数量。

期望：
- 最多 3 只。
- 若无合适候选，页面明确写“本月不买，现金等待”。

### TC-UI-004 参考价口径

步骤：
1. 查看可加仓表格的价格列。
2. 检查每个价格下方是否有交易日。

期望：
- 表头为 `参考价`。
- 价格下方显示类似 `2026-06-16 收盘`。
- 若缺少交易日，显示 `收盘参考` 或 `非实时`。
- 不允许只显示裸价格。
- 不允许表头或正文把该价格称为实时价格。

### TC-UI-005 推荐时间

步骤：
1. 查看可加仓表格里的推荐时间列。
2. 检查是否展示 AI 推荐或配仓批次生成时间。

期望：
- 每个候选都有可追溯的推荐时间或批次。
- 不允许看起来像无来源的临时手工推荐。

### TC-UI-006 超配持仓纠偏

步骤：
1. 准备或观察真实持仓体检中单只超过 25% 的标的。
2. 打开页面查看该标的所在区域。

期望：
- 超过 25% 的标的进入 `纠偏 / 不再加`。
- 超过 40% 的标的出现主动季度纠偏参考。
- 超过 50% 的标的使用严重集中措辞。
- 不允许该标的同时进入 `可加仓`。

### TC-UI-007 同赛道集中

步骤：
1. 观察可加仓候选中是否有多个同赛道标的。
2. 查看最终可加仓列表和本月不买原因。

期望：
- 同一赛道本月最多保留 1 只可加仓。
- 被过滤的同赛道标的进入 `本月不买原因`。
- 原因包含“同赛道不重复下注”或同等文案。

### TC-UI-008 本月不买原因

步骤：
1. 查看 `本月不买原因` 区域。
2. 检查候选被过滤的理由。

期望：
- 至少能覆盖偏贵、过热、同赛道重复、超配、策略阻断、缺少买入区间等原因。
- 不允许只把标的消失，不解释原因。

## 六、负向测试

### TC-NEG-001 不写 watchlist

检查点：
- 打开页面前后，`watchlist` 不应变化。
- `renderMonthlyActions()` 中不得出现写入 `/api/watchlist` 的调用。

静态检查：

```bash
rg -n "renderMonthlyActions|/api/watchlist|POST|PUT|DELETE" scripts/pipeline/build_stock_dashboard_html.py
```

期望：
- `renderMonthlyActions()` 里没有向 `/api/watchlist` 写入。

### TC-NEG-002 不写真实持仓

检查点：
- 打开页面前后，真实持仓不应变化。
- 页面不得调用真实持仓写接口。

静态检查：

```bash
rg -n "renderMonthlyActions|/api/real-holdings|POST|PUT|DELETE" scripts/pipeline/build_stock_dashboard_html.py
```

期望：
- `renderMonthlyActions()` 里没有向 `/api/real-holdings` 写入。

### TC-NEG-003 缺少策略验证文件

步骤：
1. 临时移走或模拟缺少 `data/latest/recommendation_readiness_check.json`。
2. 重新生成页面。
3. 打开 `本月动作`。

期望：
- 页面降级为只读研究参考。
- 不输出强买入信号。
- 不提高单只或总额上限。

### TC-NEG-004 缺少买入区间

步骤：
1. 模拟某候选缺少 `BUY_ZONES` 数据。
2. 重新生成页面。

期望：
- 该标的不进入可加仓。
- 页面在不买原因中说明缺少买入区间或证据不足。

### TC-NEG-005 缺少参考价交易日

步骤：
1. 模拟 `BUY_ZONES` 有价格但无 `current_trade_date`。
2. 重新生成页面。

期望：
- 页面显示 `收盘参考` 或 `非实时`。
- 不得显示 `当前价格`。
- 不得显示 `实时价格`。

## 七、验收通过标准

全部满足时通过：
- 自动化测试通过。
- 页面能正常生成。
- 页面入口、策略提示、可加仓、纠偏、不买原因都可见。
- 可加仓最多 3 只。
- 超配持仓不会进入可加仓。
- 同赛道不会重复下注。
- 参考价有交易日或非实时提示。
- 页面只读，不写 `watchlist`，不写真实持仓。

## 八、回归风险

重点回归：
- 参考价是否被误写回 `当前价格`。
- 新增买入是否绕过超配纠偏。
- 同赛道候选是否同时出现在可加仓。
- 策略验证未达标时是否仍给出过强买入措辞。
- 页面是否引入了写接口。
