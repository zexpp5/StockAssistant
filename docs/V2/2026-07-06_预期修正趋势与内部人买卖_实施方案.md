## 功能 A：分析师预期修正趋势（90 天上调/下调方向）

**回答用户什么问题**："最近分析师对这只票是越来越乐观还是越来越悲观？"（方向比增速水平更有信息量）

### A1. 数据源（先核实再开工）
- 首选：库内 `analyst_grade_events` 已有评级/目标价事件流（夜班 job 在刷）——先查它是否含 EPS 预期修正；
- 若只有评级/目标价：目标价修正方向本身即可做 V1（90 天内目标价净上调家数/净变化幅度）；
- EPS 预期修正需 FMP analyst estimates 端点（基本面端点不限流，见 [[../archive/2026-06-11 前后 FMP 限额记录]]；历史价格端点限流的教训不适用于此）。
- 🚨 别重复造轮子：`revision_ic_validation.json` 说明系统曾做过"上修因子"IC 验证（结论 FAIL 不进打分）——**本功能是展示信息不是打分因子**，两者定位不同，代码可复用其取数逻辑（先 grep）。

### A2. 输出（单一来源）
- 新 core 纯函数模块 `stock_research/core/revision_trend.py`：
  输入 90 天事件流 → 输出 `{direction: 上调中/下调中/分歧/平静, n_up, n_down, net_target_change_pct, latest_date}`
- 落进 `daily_strict_picks.json` 每只 pick 的 `revision_trend` 字段（`build_dual_track_ranking.py` 顺带算，同现有 expectation 模式）。

### A3. 展示
- 严选卡：一行 `📈 分析师风向：90 天 5 家上调 / 1 家下调 · 目标价净 +12%`（人话，无术语）；
- 方向为"下调中"时该行转橙色——**与严选逻辑冲突（新公式喜欢+分析师在撤）本身就是重要信号**。

### A4. 边界
- 不进打分公式（上修因子 IC 已 FAIL，只做展示）；不写 watchlist/持仓。

## 功能 B：内部人买卖展示（Form4 净方向）

**回答用户什么问题**："高管自己在买还是卖？"

### B1. 数据源（已在库，纯展示活）
- `stock_research/jobs/event_calendar_us_form4_daily.py` 每日在抓 SEC Form4 → 先查落库表名/字段（事件日历相关表）；
- 若现库只存"事件"粒度缺买卖金额，V1 先做"30 天内 N 笔内部人买入 / M 笔卖出"计数版。

### B2. 输出
- core 纯函数 `stock_research/core/insider_summary.py`：输入 30 天 Form4 事件 → `{n_buy, n_sell, net_direction: 净买入/净卖出/平静, latest_date}`
- 同样落 `daily_strict_picks.json` 的 `insider` 字段。

### B3. 展示
- 严选卡一行：`👔 内部人：30 天 3 笔买入 / 0 卖出（净买入）`；
- 净卖出转橙色；无数据显示"30 天无申报"（不显示 ⚪ 假灯）。
- ⚠️ 文案注意：高管卖出常见于报税/行权，**卖出≠看空**，悬停 tooltip 必须带这句免责，避免新手误读；买入信号权重大于卖出。

## 通用硬规则（两功能共用）

1. **后端算好前端只渲染**（单一来源，禁止 JS 复算）；
2. 展示信息**不进打分公式**、不写 watchlist、不写持仓、无买卖指令文案（advisory 边界）；
3. 独立只读 job/脚本连库必须 `force_read_only=True`（写锁重试，别用假只读）；
4. 改 dashboard 只改 `HTML_TEMPLATE` 后跑 `./build_dashboard.sh`；解释器用 `/opt/homebrew/bin/python3`；
5. 每个功能一个 commit，测试跟功能同 commit。

## 验收标准（做完逐条 ✅/❌ 自己跑给用户看）

1. `daily_strict_picks.json` 每只 pick 含 `revision_trend` + `insider` 字段，值与手工 SQL 抽查一致（至少抽 2 只）。
2. 严选卡每张出现"分析师风向"与"内部人"两行，人话、无术语（momentum/IC 等字样不得出现）。
3. 分析师下调中 / 内部人净卖出时对应行为橙色；内部人卖出行悬停有"卖出常见于报税/行权，≠看空"免责。
4. 无数据时显示"90 天无修正记录 / 30 天无申报"，不显示假灯、卡不塌。
5. 两个 core 模块单测全过且不连库（纯函数喂 dict）；集成后 `test_daily_strict_picks` 回归过。
6. 全程无一行写库（只读探查 + 读 JSON），`git diff` 不含任何 DELETE/INSERT price_daily/watchlist 语句。
