## 一、先回答"页面上的数字是不是错的"（已逐项核实，2026-07-02）

### 1.1 顶部红块「能不能照着买」—— 数字没算错，但口径旧且与全页打架

| | 红块显示（1d） | 数据源 |
|---|---|---|
| A股 | alpha -0.75% · 命中 41.3% · n=537 | `data/latest/shadow_tuning_evidence.json` |
| 港股 | alpha +0.39% · 命中 54.3% · n=300 | 同上 |
| 美股 | alpha -0.31% · 命中 51.3% · n=630 | 同上 |

- 渲染函数：`build_stock_dashboard_html.py` 的 `_build_trust_light`（约 L19377）。
- **数字与其数据源一致，不是算错**。但这是**影子调参累计口径**（含旧公式时期、全部历史影子样本）。
- 而页面下方验证卡和 `alpha_trend.json` 用的是 **strategy_eval 口径**（当前 strategy_version + 2026-05-25 cutoff + 每天最后一批去重）：美股 1d **-0.18% n=288** / 港股 **+0.29% n=132**。
- 两套口径结论方向一致（都未达标），但样本数 630 vs 288 同屏出现 = 用户必然懵。**病根：违反"事实一处"低噪原则。**

### 1.2 🚨 真 bug：A 股 alpha 走势永远 n=0（本次核查新发现）

- `stock_research/jobs/alpha_trend_logger.py` L34：`MARKETS = ("US", "HK", "A")`。
- `strategy_eval.mature_samples` 按 `rp.market = ?` 精确匹配，而 `recommendation_picks.market` 里 A 股存的是 **"CN"**。
- → 走势记录里 A 股每天都是 `n=0`，静默漏记。与 [[incident_watchlist_market_value_inconsistent]]（'US'/'美股' 不统一漏掉 MU）同款 footgun。
- **修法**：`MARKETS = ("US", "HK", "CN")`（改一处；历史 A 股走势数据无法补，接受断档并在图上注明）。已登记进 `已知问题清单.md`。

### 3.1 信任灯收成一行（首屏第 1 元素）

- 保留 `_build_trust_light` 的红/黄/绿判定逻辑，但**数据源换成 strategy_eval 同源**（与 `alpha_trend.json` 一致），三市场明细、达标线说明全部移入 `<details>` 折叠。
- 影子调参口径（shadow_tuning_evidence）的数字**只出现在折叠的"系统自检与验证细节"技术区**，并标注口径名，不再与主口径同屏。
- 折叠头文案示例：`🔴 现在不能照着买 · 美股样本外 alpha -0.18%（n=288）未转正 ▸ 点开看三市场明细`

### 3.2 🎯 今日严选 3 只（首屏第 2 元素，本次新增的唯一新功能）

**单一来源原则：后端算好，前端只渲染**（[[feedback_single_source_no_double_engine]]）。

生成规则（2026-07-02 已人工跑通验证，当日产出 = AVGO / AMZN / NXPI）：

```
输入池 = dual_track_ranking.json → markets.US.candidate_focus_top10（新公式美股精选 Top10）
过滤1（剔贵）:   buy_zone.compute_buy_zones() 价格位置 = 🔴偏贵 → 剔除
                （当日剔 INTU $266>区间上沿 / QCOM $189 / MSFT $369）
过滤2（剔接飞刀）: price_daily 近 20 个交易日收盘跌幅 ≤ -20% → 剔除
                （当日剔 ORCL -27.5% / ON -28.4% / CRM -24.7%；
                 规则沿用 [[project_premarket_buy_avoid_card]] 的 ABC 富集⚠️接飞刀线）
排序:            过滤后按新公式名次升序，取前 3。
                 🟢便宜 与 🟡区间内 都可入选（🟢不加分——便宜可能是在跌，不奖励）。
不足 3 只时:     有几只显示几只，空位显示"今日无合格严选"，绝不硬凑。
```

**每只票的展示字段**（全部后端生成，写入 JSON）：
- `symbol / name / 一句话干什么的`（复用 `chain_metadata.layman_intro`，缺则实施者补 `_plain_intro` 映射）
- `为什么上榜`（一句话：新公式名次 + 老公式名次是否也认可 + 评级/质量亮点，用 `_plain_reason()` 风格大白话）
- `价格位置`（buy_zone `format_line(compact=True)` 现成格式：`💰 $340~$412 · 现价 $372 🟡`）
- `风险一句`（近 20 日跌幅 >12% 时必须写"整个板块在跌，分批小仓"）
- 卡片底部固定一行：`研究严选 ≠ 买入指令；整套策略样本外未达标（见顶灯）`（[[feedback_advisory_not_directive]]）

**产物落点**：新增 `data/latest/daily_strict_picks.json`，由 `build_dual_track_ranking.py` 顺带产出（它已经算了精选 Top10，加过滤即可，不另起 job、不多开 DB 连接）。

**早报同步**：`morning_brief.py` 美股段顶部加"🎯 今日严选"3 行（复用同一 JSON，slim 风格 2 行/只，遵守 [[feedback_feishu_card_too_long]]）。

### 3.3 主榜 Top10（首屏第 3 元素）

- 现表格保留（含市场 tab、新规则优先排序、观察池折叠），但表格上方的「怎么看新规则」「数据够不够用」两块移入折叠。

### 3.4 双轨面板收缩

- 默认只显示一行摘要头：`美股规则双轨 · Top5 +2.88pp / Top10 +1.51pp / Top20 +0.56pp · 切换标准 1/4 🔒`，点开才是三张卡+Top10 对照表+止损闸明细。
- 止损闸有破位票时（红条），红条**提升到首屏严选卡下方**不折叠——这是唯一允许上首屏的告警。

## 六、附录：「数据够不够用」45 只成因分析与修法（2026-07-03 补，随本次改版一起做）

用户问"这些数据没拉到是什么原因"，逐只核查后结论：**45 只里 43 只不是拉取失败，是估值口径不适合亏损成长股；另抓到 1 个真价格 bug（HON）+ 1 个快照滞后问题。**

### 6.1 成因核查结论（2026-07-03 已验证）

| 桶 | 数量 | 真实原因 | 现有提示对不对 |
|---|---|---|---|
| 数据质量待查 | 27（S/MP/TLN/WULF 等） | 全部卡 69.8 分 = 字段覆盖 7/9（77.8）− 8（仅 1 个正估值字段）。缺的 2 个字段是 trailing_pe 和 peg_ratio——**公司亏损/刚扭亏，这两个指标天生不存在**，任何数据源都给不出，"补数据"按钮无效（所以可自动补=0 是对的） | ❌ 文案误导："先查缺失字段来源，补齐后再允许买入"——没有可补的 |
| 估值口径不适用 | 16（RKLB/ASTS/LAC/SOUN 等） | 同样 7/9 覆盖且 Forward PE 为负（亏损）→ 零正估值字段：77.8 − 20 = 57.8 | ✅ 正确，"改看收入增速/EV/Sales" 是对的动作 |
| 只适合研究/复查 | 2 | TTMI 一周 -12.4% = 真事件 ✅；**HON "单日 -50.9%" = 假信号**：2026-07-03 用 yfinance 复核，HON 近一个月稳定在 $220~232 无暴跌。库内异常 K 线几乎确定是**霍尼韦尔分拆后价格未复权**（公司正拆成三家），把 corporate action 当成了暴跌 | ❌ HON 是我们的数据 bug |

另发现：这批快照 `trade_date=2026-06-29`，比审计时间（07-02 晚）旧约 2 个交易日，未超 `_STALE_SOURCE_DAYS` 阈值所以没报警，但当日排序实际用的是 3 天前行情。
